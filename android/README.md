# VenueOne Android app (Trusted Web Activity)

The Android build wraps the live PWA at <https://venueone-team.vercel.app/app> in a
Trusted Web Activity. The app ships no venue data: every screen is the same web app,
so a new venue or an edited price reaches installed phones on the next refresh.

Only two files here are source: `twa-manifest.json` and this README. Everything else
in this folder is generated by Bubblewrap and is ignored by git.

## What is committed

| File | Purpose |
| --- | --- |
| `twa-manifest.json` | Package id, host, colours, icons, signing key and release fingerprint. |
| `README.md` | Build and release notes. |

## Toolchain

Measured with:

- JDK 17
- Android SDK: platform `android-36`, build-tools `36.1.0`
- Gradle 8.11.1 (the wrapper version pinned by the Bubblewrap template)
- `@bubblewrap/cli` (latest, installed with npm)

`bubblewrap doctor` must report that the JDK and SDK paths are valid before building.

## Build

The release keystore lives outside the repository at
`C:\Users\PRAJWAL\.venueone\venueone-release.jks`, alias `venueone`. Its passwords are
in `C:\Users\PRAJWAL\.venueone\keystore.properties` and are never committed. The
manifest points at that path, so a different machine needs its own keystore and its
own fingerprint in `twa-manifest.json` and `public/.well-known/assetlinks.json`.

Build from this folder, because Bubblewrap runs Gradle in the current directory:

```powershell
$props = Get-Content "$env:USERPROFILE\.venueone\keystore.properties"
$env:BUBBLEWRAP_KEYSTORE_PASSWORD = (($props | Where-Object { $_ -like "storePassword=*" }) -replace "^storePassword=","")
$env:BUBBLEWRAP_KEY_PASSWORD = (($props | Where-Object { $_ -like "keyPassword=*" }) -replace "^keyPassword=","")
bubblewrap build --manifest=twa-manifest.json --directory=.
```

Outputs, all ignored by git:

| File | Size | Notes |
| --- | --- | --- |
| `app-release-signed.apk` | 1,181,462 bytes | Sideload this on a phone. |
| `app-release-bundle.aab` | 1,248,434 bytes | For a future Play Console upload. |
| `app/build/outputs/` | n/a | Unsigned intermediates. |

`bubblewrap build` regenerates the whole Android project from the template plus
`twa-manifest.json` when the manifest checksum changes, then builds and signs. If the
checkbox prompt about regenerating appears, answer yes.

The SHA-256 digest above is the release fingerprint stored in `twa-manifest.json` and
in `public/.well-known/assetlinks.json`.

## Full-screen mode

Without Digital Asset Links the app still runs, but Chrome shows the page inside a
browser tab with a URL bar. The link is verified when
`https://venueone-team.vercel.app/.well-known/assetlinks.json` returns the package name
and the release fingerprint. That file is served from `public/.well-known/assetlinks.json`
and is part of the deployed site.

## Limits

- `minSdkVersion` is 24 because the Android Browser Helper library requires it.
- `targetSdkVersion` is 36, so Android 15 and 16 apply edge-to-edge layout. The app shell
  already uses safe-area insets.
- The APK is built and inspected here but was not installed on a physical device in this
  environment. Sideloading and a Play Console release are separate steps.
- Google sign-in and UPI or card payments open in the real Chrome engine, so cookies and
  payment intents behave as they do in the browser.
